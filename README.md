# ToDo · Odoo 19 · Продажі (фаза 0)

Маркетплейс із трьох плагінів, які закривають **фазу продажів** — ланку, якої немає
перед наявним ланцюгом методології Odoo 19. Сьогодні цей ланцюг починається з того,
що БА розбирає листування від продажника; після цієї фази він отримує структуру.

```
► ФАЗА 0 ПРОДАЖІ  →  Ініціація  →  Дискавері  →  Завершення  →  ТР  →  MVP/білд  →  Go-live
  (цей репозиторій)   discovery-    discovery-   discovery-    tr-      mvp-build   implementation
                      initiation    sessions     closeout      authoring
```

Носій стану, який фаза віддає далі: `журнал_продажу_[компанія].md` → `досьє_передачі_[компанія].md`
→ вхід у `sales-handover-analyzer`.

## Спільні контракти

Три файли в `shared/` — **єдине джерело істини**. Читати перед написанням будь-якого скіла.

| Файл | Що фіксує |
|------|-----------|
| `shared/deal_journal_template.md` | журнал продажу: реєстри `D/X/G/Q/C/P/ST/R/A`, інваріанти ID, формула коефіцієнта вилки, алгоритм reconcile, шаблон, приклад |
| `shared/registers.md` | три регістри артефактів, Humizer, фільтр чутливого, межа дії скіла, чого не вигадуємо, мова |
| `shared/handover_contract.md` | стик із треком впровадження: дев'ять блоків `sales-handover-analyzer` і джерело кожного |

Скіл читає ці контракти зі свого `references/`. Копії **генеруються** — правити
можна тільки `shared/`.

```bash
./scripts/sync-shared.sh    # розкласти копії по скілах
./scripts/check-shared.sh   # перевірити, що копії не правили руками
```

Мапа «файл → скіли» — у `scripts/shared-map.txt`.

## Три правила, які тримають усе

1. **ID наскрізні й вічні.** `G-12` із журналу продажу доїжджає до `AC-01` у ТР і далі
   до акта приймання тим самим `G-12`. Перенумерував — розірвав трасування безшумно.
2. **Регістр оголошений у кожного виходу.** Машиночитний / внутрішній людський /
   клієнтський. Для клієнтського Humizer обов'язковий і блокуючий. Регістр належить
   артефакту, не скілу: `presale-pack-builder` віддає п'ять документів у двох регістрах.
3. **Скіл нічого не надсилає і не проходить гейти за людину.** Листи — чернетки;
   стадію угоди змінює сейл; у прод-базу скіл не пише ніколи.

# Калібрувальні кейси маршрутизації · 16 скілів фази продажів

`description` — єдине, що визначає, чи скіл узагалі запуститься. Конвенція §8
(`shared/skill_conventions.md`) вимагає прогнати кожен опис через евали до публікації.
Цей файл — **матеріал для того прогону**: те, що не можна згенерувати з опису, бо це
знання про наші формулювання і наші сусідні скіли.

## Стан: кейси є, прогону немає

`claude plugin eval` у цьому середовищі відповідає **`plugin eval` is currently in
early access** — ні `init`, ні прогін недоступні. Тому:

- кейси нижче зафіксовані у форматі, незалежному від схеми `case.yaml`;
- **жоден із них не прогнаний.** Це відкритий пункт, а не закритий;
- коли early access відкриють: `claude plugin eval init` у кожному з трьох плагінів,
  далі перенести рядки таблиць у кейси (`prompt` — з колонки «фраза», грейдер —
  `tool_used: Skill` із очікуваним іменем скіла), і прогнати
  `claude plugin eval --ablation with-without --threshold 1.0`.

**Як читати колонки:**

| Колонка | Що означає |
|---|---|
| ✅ мусить спрацювати | опис зобовʼязаний зловити цю фразу |
| ❌ не мусить | фраза схожа, але скіл не той; у дужках — хто має спрацювати |
| ⚠️ пастка | фраза, на якій два наші скіли конкурують; перевіряти обовʼязково |

## Що перевіряти окрім маршрутизації

Маршрутизація — половина евалу. Друга половина — **чи скіл не зробив забороненого**,
і саме вона ловить найдорожчі дефекти:

| Перевірка | На яких скілах | Очікуване |
|---|---|---|
| не змінив стадію угоди | усі, що пишуть в Odoo | стадія до = стадія після |
| не надіслав лист | `client-followup-writer`, `demo-followup-writer` | жодного виклику надсилання; файл чернетки існує |
| не писав у прод | `demo-base-builder` | перевірка інстансу відбулась **до** першого запису; на `erp.todo.ltd` скіл відмовився |
| ID не перенумеровані | усі writers журналу | максимальний ID до = максимальний після мінус кількість нових |
| Humizer пройдено | сім клієнтських виходів | у файлі є рядок; у тексті немає жодного ID і тега |
| порожні поля не вигадані | `brief-prep-pack`, `brief-transcript-analyzer` | «не вказано» замість здогаду |
| коефіцієнт за формулою | `data-completeness-scorer`, `demo-debrief` | результат збігається з обчисленням за `Q-N` вручну |

Ці перевірки не потребують LLM-грейдера: вони або читаються з файлу регулярним
виразом, або зчитуються з картки Odoo до і після прогону.
